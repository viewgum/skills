# upload-preflight: a 95 second test clip for the publishing APIs

Run on 2026-11-19 by an agent following `skills/upload-preflight/SKILL.md`, with shortform-preflight at commit af79865 and
FFmpeg 7.1. The clip is a generated test pattern (1080 x 1920, 23.976 fps, AAC 44.1 kHz mono), the kind a render pipeline writes
with default settings. The person posts through a scheduler, so the publishing API rules were used.

The clip, to repeat this run:
`ffmpeg -f lavfi -i "testsrc2=size=1080x1920:rate=24000/1001:duration=95" -f lavfi -i "sine=frequency=440:duration=95:sample_rate=44100" -c:v libx264 -pix_fmt yuv420p -c:a aac -b:a 128k -shortest demo-1080x1920.mp4`

**File:** demo-1080x1920.mp4 · 1080 x 1920 · 95 s · 23.976 fps · H.264 · AAC (LC) 44.1 kHz mono · 156.04 MB
**Rules:** publishing APIs (`--api --platform facebook-reels,instagram-reels`)

| App | Result | Failing or warning rows |
|---|---|---|
| Facebook Reels | fail | length 95 s (the API takes 3 to 90 s); frame rate 23.976 fps (24 to 60, average); sample rate 44.1 kHz (48 kHz listed, warn); mono (stereo listed, warn) |
| Instagram Reels | fail | edit list present (no edit lists); moov atom after the media (at the front) |

### Fix

One re-encode covers every row (sources: Meta for Developers, Reels Publishing API and IG User Media reference):

`ffmpeg -i demo-1080x1920.mp4 -t 89.9 -r 30 -c:v libx264 -crf 18 -pix_fmt yuv420p -c:a aac -b:a 192k -ar 48000 -ac 2 -g 90 -movflags +faststart -use_editlist 0 fixed.mp4`

The audio is set to 192k because a file encoded at exactly 128k measured just under the Facebook API's "128 kbps or more", which
the checker reports as a warning.

**After the fix:** `0 fail, 0 warn, 29 pass, 4 info`, exit code 0.

Info rows (the container, the exact frame size and the like) are not failures and were left out.
